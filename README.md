# FX Signals

Воспроизводимый сигнальный слой для коммуникаций о трансграничных переводах в коридорах
`RUB→AMD`, `RUB→KZT`, `RUB→KGS`, `RUB→TJS` и `RUB→UZS`.

Система решает две задачи:

- рассчитывает итоговые коммуникационные сигналы на произвольную дату среза без использования
  будущих данных;
- воспроизводит walk-forward-бэктест правил, LogReg и CatBoost на пяти временных горизонтах.

ML-модель определяет, есть ли повод для коммуникации. После этого метаалгоритм выбирает один
понятный индикатор, подставляет проверенный текст и применяет cooldown и недельный лимит.

## 1. Окружение

Для запуска нужны:

- Python 3.12 или новее;
- [uv](https://docs.astral.sh/uv/);
- доступ в интернет при первичной установке зависимостей и загрузке курсов.

Все команды ниже выполняются из корня репозитория.

```bash
# Клонируем репозиторий и переходим в него.
git clone https://github.com/kostkornilov/fx-signals.git
cd fx-signals

# Создаём окружение строго по uv.lock, включая pytest и Ruff.
uv sync --extra dev --frozen
```

## 2. Данные

Проект использует только открытые официальные курсы из
[XML API Банка России](https://www.cbr.ru/development/SXML/). Основные ряды — AMD, KZT, KGS,
TJS и UZS; USD, EUR и CNY используются как рыночный контекст для группы признаков `D`.

Период зафиксирован в [`configs/data.yaml`](configs/data.yaml): с 1 января 2019 года по
2 сентября 2026 года. Поэтому повторный запуск использует тот же исторический интервал и не
сдвигается при публикации новых курсов.

```bash
# Загружаем основные и контекстные ряды ЦБ.
uv run fx-signals data fetch --config configs/data.yaml
```

Команда создаёт локально:

- `data/raw/cbr/baseline-2019-2026/rates.csv` — пять целевых валют;
- `data/raw/cbr/baseline-2019-2026/context_rates.csv` — USD, EUR и CNY;
- `data/raw/cbr/baseline-2019-2026/manifest.json` — URL запросов, число строк и SHA256 файлов.

Сырые данные не хранятся в Git. Для каждой записи сохраняются `effective_date` и `available_at`.
В текущем дневном прототипе `available_at` консервативно равен дате действия курса.

## 3. Инференс на дату среза

Инференс отвечает на вопрос: «Какие коммуникации система сформировала бы на дату `T`, имея
только доступную к этому моменту информацию?»

```bash
# Считаем сигналы на выбранную дату и сохраняем их в отдельный CSV.
uv run fx-signals signals \
  --config configs/signals.yaml \
  --as-of 2026-09-02 \
  --output artifacts/signals/2026-09-02.csv
```

Перед расчётом система удаляет все строки с `available_at > T`, заново строит признаки, обучает
модель на прошлом, калибрует порог на предшествующем валидационном периоде и только затем оценивает
срез. По умолчанию используется `CatBoost (A,B,C,D)` с таргетом `stay_not_worse` на горизонте
пяти свежих публикаций.

После модельного фильтра метаалгоритм выбирает один разрешённый положительный индикатор, разрешает
конфликты по силе и понятности, применяет трёхдневный cooldown и лимит не более двух сигналов на
коридор в календарную неделю. Тексты уведомлений и запрещённые формулировки находятся в
[`configs/texts.yaml`](configs/texts.yaml).

Выходной CSV содержит только рекомендованные коммуникации:

- дату среза, дату использованного курса и валютный коридор;
- индикатор, направление, силу и скорость;
- рекомендованный сценарий, заголовок и тело push-уведомления;
- score модели, порог и аудируемую причину выбора метаалгоритма.

Отсутствие строк в CSV — штатный результат: на выбранную дату модель могла не найти достаточно
надёжного и объяснимого повода для коммуникации. Если `--output` не указан, файл записывается в
`artifacts/signals/signals-<дата>.csv`.

## 4. Walk-forward-бэктест

Бэктест проверяет правила и модели на данных, которые следуют строго после обучающего и
валидационного периодов.
Обучение выполняется на таргете `h=5`, итоговый поток оценивается отдельно на горизонтах
`h=1/3/5/10/20`. Последний период, начиная с 1 сентября 2025 года, остаётся final OOT и не
участвует в обучении или выборе порога.

```bash
# Полностью пересчитываем модели, итоговую коммуникационную политику и отчёт.
uv run fx-signals backtest-report --config configs/backtest_report.yaml
```

Метаалгоритм, список разрешённых сценариев, cooldown и недельный лимит в бэктесте совпадают с
инференсом. Это позволяет оценивать не сырой score модели, а поток, который действительно мог бы
стать коммуникацией.

Результаты записываются в:

- `reports/backtest/backtest_metrics.csv` — все методы, коридоры, периоды и горизонты;
- `reports/backtest/REPORT.md` — краткий вывод и ограничения;
- `reports/tables/ml_summary_lift.csv` — итоговая OOT-витрина;
- `artifacts/backtest/thresholds.csv` — выбранные пороги по временным фолдам;
- `artifacts/backtest/manifest.json` — версия Python, пакетов, Git-коммит и SHA256 входных данных.

При необходимости границы проверки можно переопределить, не меняя YAML:

```bash
# Пример собственного периода; параметры должны оставлять достаточно истории для train/validation.
uv run fx-signals backtest-report \
  --config configs/backtest_report.yaml \
  --first-test-year 2022 \
  --oot-start 2025-09-01 \
  --end 2026-09-02
```

## 5. Проверки

Тесты используют синтетические данные и не требуют сети. Среди них есть отдельная проверка, что
изменение любых наблюдений после даты среза не влияет на результат инференса.

```bash
# Запускаем все автоматические тесты.
uv run pytest

# Проверяем стиль и статические ошибки.
uv run ruff check src/fx_signal
```

## 6. Семантика и ограничения

`rub_per_unit = value_rub / nominal` — число рублей за единицу валюты получателя. Чем оно ниже,
тем больше валюты получит адресат за одинаковую сумму в рублях. Текст уведомления сообщает только
проверяемый факт о прошлом или настоящем и не обещает будущий курс.

Основные ограничения решения:

- курс ЦБ является воспроизводимым прокси, а не фактическим курсом исполнения в приложении банка;
- дневные данные не позволяют моделировать внутридневное изменение курса;
- клиентский таргетинг и общий лимит всех банковских коммуникаций не моделируются без внутренних
  клиентских данных; реализован рыночный лимит на уровне коридора;
- положительная офлайн-метрика должна быть подтверждена пилотом с реальными курсами исполнения и
  контрольной группой.
